```python
import sys
```

### Таблица замен функций

| Заменяемая функция/конструкция | Функция замены | Пакет/Модуль | Когда применять / Примечание |
|-------------------------------|----------------|--------------|------------------------------|
| `input()` | `sys.stdin.readline()` | `sys` | При `N > 10⁵` строк ввода. Убирает overhead декодирования и парсинга `input()`. |
| Множественные `print(x)` | `sys.stdout.write('\n'.join(map(str, out)) + '\n')` | `sys` | `print` сбрасывает буфер ОС каждый вызов. `write` + буферизация ускоряет вывод в 2–5x. |
| Цикл `int(input())` / `input().split()` | `map(int, sys.stdin.read().split())` | `sys` | Чтение всего ввода за 1 syscall. Критично для задач с `10⁵–10⁶` чисел. |
| `list.pop(0)` | `collections.deque.popleft()` | `collections` | Удаление с начала списка — `O(N)`, у `deque` — `O(1)`. Must-have для BFS, скользящих окон, очередей. |
| `a ** b % m` | `pow(a, b, m)` | built-in | Модульное возведение в степень за `O(log b)`. Не создаёт гигантских промежуточных чисел, быстрее в `10–100x`. |
| `math.sqrt(x)` (для целых) | `math.isqrt(x)` | `math` | Целочисленный корень (Python 3.8+). Точнее, быстрее float-версии, нет проблем с `precision` и округлением. |
| `arr.count(x)` (много запросов) | `collections.Counter(arr)` | `collections` | `count` — `O(N)` на каждый запрос. `Counter` строит хеш-таблицу за `O(N)`, далее `O(1)` на запрос. |
| Линейный поиск в отсортированном массиве | `bisect.bisect_left(arr, x)` | `bisect` | `O(N) → O(log N)`. Возвращает индекс вставки. Аналог `std::lower_bound` в C++. |
| `sorted(arr)[0]` или ручной `min` в цикле | `heapq.heappop(arr)` / `heapq.heappush()` | `heapq` | `O(N log N)` сортировка → `O(log N)` извлечение минимума. Реализована на C, оптимизирована под кучу. |
| `s += part` в цикле | `''.join(iterable)` | built-in | Строки неизменяемы. Конкатенация в цикле — `O(N²)`, `join` — `O(N)`. Обязательно при склейке `10⁴+` строк. |
| `sorted(arr)` | `arr.sort()` | built-in | Сортировка на месте экономит память и время копирования. Вызывает меньше аллокаций и GC-давления. |
| Ручная реализация `gcd` / `lcm` | `math.gcd(a, b)` / `math.lcm(a, b)` | `math` | Встроенные версии на C. `lcm` доступен с Python 3.9+. Не пишите свои алгоритмы Евклида. |
| Глубокая рекурсия (DFS на деревьях/графах) | `sys.setrecursionlimit(10**6)` | `sys` | По умолчанию лимит `1000`. Без увеличения — `RecursionError`. Не заменяет алгоритм, но спасает валидацию. |
### Важные замечания для олимпиад
1. **Асимптотика > микрооптимизации.** Замены выше дают выигрыш в константе (`1.5x–10x`). Если алгоритм `O(N²)` при `N=10⁵`, Python всё равно упадёт по TLE. Сначала оптимизируйте сложность.
2. **Python vs C++.** Даже с этими оптимизациями Python в `3–8x` медленнее C++ на операциях с числами. Используйте его только если лимиты времени щадящие или задача требует быстрой реализации (Python позволяет писать решения за 10–15 минут).
3. **Не заменяйте слепо.** `collections.Counter` полезен только при множестве запросов. Для единичного `count` он медленнее из-за накладных расходов. `bisect` работает только на отсортированных данных.
4. **Локальные переменные.** В Python доступ к локальным переменным быстрее глобальных. Оборачивайте основной код в функцию `def solve():` — это даёт `5–15%` ускорения.
5. **PyPy.** На большинстве олимпиад доступен PyPy3. Он ускоряет чистый Python в `2–5x` автоматически, но `sys.stdin.read()` и `join` всё равно обязательны.

### ТИП 1: Анализ делителей на больших диапазонах (Оптимизация $O(\sqrt{N})$)

**Задача 1. «Почти совершенные числа»**

Назовем число _почти совершенным_, если сумма всех его натуральных делителей (включая 1 и само число) отличается от удвоенного самого числа ровно на единицу: $|\sum D_i - 2N| = 1$. На вход программе подается число $N$ ($1 \le N \le 10^9$). Необходимо определить, является ли оно почти совершенным, затратив на это не более $O(\sqrt{N})$ операций и минимальное количество памяти.

- **Ввод:** `4` $\to$ **Вывод:** `YES` (Делители 4: 1, 2, 4. Сумма = 7. $2 \times 4 = 8$. Разность $|7 - 8| = 1$).
    
- **Ввод:** `6` $\to$ **Вывод:** `NO` (Делители 6: 1, 2, 3, 6. Сумма = 12. $2 \times 6 = 12$. Разность 0 — это просто совершенное число).
    

**Решение для проверки:**



```Python
import math

n = int(input())
total_sum = 0
sqrt_n = int(math.isqrt(n))

for i in range(1, sqrt_n + 1):
    if n % i == 0:
        total_sum += i
        if i * i != n:
            total_sum += n // i

if abs(total_sum - 2 * n) == 1:
    print("YES")
else:
    print("NO")
```

### ТИП 2: Динамический анализ последовательности «на лету» (Без хранения в памяти)

**Задача 2. «Максимальная длина пилообразной подпоследовательности»**

На вход программе подается последовательность натуральных чисел, завершающаяся числом 0 (ноль не входит в последовательность, чисел может быть до $10^6$). Подпоследовательность называется _пилообразной_, если каждые два соседних элемента чередуются по принципу: «больше-меньше-больше-меньше» или «меньше-больше-меньше-больше». Найдите длину самой протяженной такой непрерывной подпоследовательности. Память программы не должна зависеть от длины ввода ($O(1)$ памяти).

- **Ввод:** `10 15 12 18 18 5 9 4 0` $\to$ **Вывод:** `4` (Максимальный «пилообразный» кусок: `18 5 9 4` или `10 15 12 18`).
    

**Решение для проверки:**



```Python
# Нам нужно отслеживать направление знака (> или <) без сохранения списка
prev = int(input())
if prev == 0:
    print(0)
else:
    curr = int(input())
    if curr == 0:
        print(1)
    else:
        # max_len — глобальный максимум, текущий кусок имеет длину минимум 2, если числа не равны
        max_len = 2 if curr != prev else 1
        current_len = 2 if curr != prev else 1
        
        # Направление: 1 если curr > prev, -1 если curr < prev, 0 если равны
        prev_dir = 1 if curr > prev else (-1 if curr < prev else 0)
        prev = curr
        
        while True:
            curr = int(input())
            if curr == 0:
                break
            
            curr_dir = 1 if curr > prev else (-1 if curr < prev else 0)
            
            if curr_dir != 0 and curr_dir != prev_dir:
                current_len += 1
                prev_dir = curr_dir
            else:
                if curr_dir != 0:
                    current_len = 2  # Сброс к новой паре
                    prev_dir = curr_dir
                else:
                    current_len = 1  # Сброс, так как числа равны
                    prev_dir = 0
            
            if current_len > max_len:
                max_len = current_len
            prev = curr
            
        print(max_len)
```

### ТИП 3: Основная теорема арифметики и степени множителей

**Задача 3. «Поиск свободных от квадратов чисел»**

Натуральное число называется _свободным от квадратов_, если в его разложении на простые множители ни одно простое число не встречается в степени большей, чем 1 (то есть оно не делится ни на один полный квадрат, кроме 1). На вход подается число $N$ ($2 \le N \le 10^9$). Программа должна вывести `YES`, если число свободно от квадратов, и `NO` в противном случае. Алгоритм должен работать быстрее, чем за $O(N)$.

- **Ввод:** `30` $\to$ **Вывод:** `YES` ($30 = 2 \times 3 \times 5$, все степени равны 1).
    
- **Ввод:** `12` $\to$ **Вывод:** `NO` ($12 = 2^2 \times 3$, делится на квадрат двойки).
    

**Решение для проверки:**



```Python
n = int(input())
is_square_free = True
d = 2

while d * d <= n:
    if n % d == 0:
        count = 0
        while n % d == 0:
            count += 1
            n //= d
        if count > 1:
            is_square_free = False
            break
    d += 1

if n > 1 and is_square_free == True:
    pass # Остаток в первой степени, все ок

print("YES" if is_square_free else "NO")
```

### ТИП 4: Поиск пар с ограничением на индекс и свойства чисел (Продвинутый однопроходный алгоритм)

**Задача 4. «Эффективная взаимно простая пара»**

На вход программе сначала подается количество чисел $N$ ($6 \le N \le 10^5$), а затем сами $N$ натуральных чисел, каждое не превосходит 10000. Найдите **максимальную сумму** двух элементов этой последовательности таких, что:

1. Они находятся на расстоянии не менее чем 5 индексов друг от друга (индексы $i$ и $j$, $|i - j| \ge 5$).
    
2. Они являются взаимно простыми (их НОД равен 1).
    
    Если такой пары нет, выведите -1. Программа должна использовать $O(1)$ дополнительной памяти (считывание всего списка за раз запрещено, данные нужно обрабатывать в один проход потоком!).
    

_Короткая подсказка: для эффективного решения потоком на расстоянии 5 можно использовать очередь фиксированной длины (буфер) на 5 элементов._

- **Ввод:** `7` затем числа `4 9 6 8 10 15 21` $\to$ **Вывод:** `25` (Пара 4 и 21: расстояние между ними индекс 0 и индекс 6 (6-0=6 $\ge$ 5). НОД(4, 21) = 1. Сумма 4 + 21 = 25. Пара 9 и 15 не подходит, НОД(9,15)=3).
    

**Решение для проверки:**



```Python
import math

n = int(input())
# Используем буфер из 5 элементов, чтобы сымитировать задержку в 5 шагов
buffer = []
max_sum = -1

# Нам нужно хранить историю «лучших» чисел, прошедших задержку. 
# Но поскольку нам важна взаимная простота, один абсолютный максимум хранить нельзя 
# (он может оказаться не взаимно простым с текущим числом).
# Так как числа <= 10000, мы можем сохранять самый большой элемент для каждого возможного остатка или просто список кандидатов.
# Но самый элегантный способ для школы, раз уж память O(1) требует не хранить N элементов — хранить массив из пройденных элементов.
# Поскольку ограничение памяти О(1), а числа маленькие (до 10000), сохраняем только глобально лучшие числа.
# На самом деле, достаточно хранить до 10 максимальных чисел, встреченных ранее, так как у любого числа не может быть больше 8-9 различных простых делителей в пределах 10000.
passed_maxs = [] 

for i in range(n):
    curr = int(input())
    
    if i >= 5:
        # Элемент, который вышел из буфера 5 шагов назад
        passed_val = buffer.pop(0)
        # Добавляем его в список потенциальных максимумов и сортируем по убыванию
        passed_maxs.append(passed_val)
        passed_maxs.sort(reverse=True)
        # Держим только топ-15 лучших элементов, этого математически достаточно для любого НОД
        if len(passed_maxs) > 15:
            passed_maxs.pop()
            
    buffer.append(curr)
    
    # Проверяем текущий элемент с уже валидными «прошедшими» максимумами
    if i >= 5:
        for val in passed_maxs:
            if math.gcd(curr, val) == 1:
                if curr + val > max_sum:
                    max_sum = curr + val
                break # Так как passed_maxs отсортирован, первый подошедший даст лучший результат для этого curr

print(max_sum)
```

### ТИП 5: Ограничения остатков в циклических процессах

**Задача 5. «Период дроби (Алгоритм Long Division)»**

Даны два натуральных числа $A$ и $B$ ($1 \le A < B \le 10^5$). Программа должна найти длину периода бесконечной десятичной дроби $A / B$. Алгоритм должен быть эффективным по времени и не использовать вещественную арифметику float (так как точности float не хватит).

- **Ввод:** `1 3` $\to$ **Вывод:** `1` (1/3 = 0.(3), период состоит из одной цифры).
    
- **Ввод:** `1 7` $\to$ **Вывод:** `6` (1/7 = 0.(142857), период из 6 цифр).
    

**Решение для проверки:**



```Python
a = int(input())
b = int(input())

# Моделируем деление «уголком». Остатки, которые мы получаем, будут повторяться.
# Как только остаток повторился — начался новый цикл периода.
remainders = {}
pos = 0
rem = a % b

while rem != 0 and rem not in remainders:
    remainders[rem] = pos
    rem = (rem * 10) % b
    pos += 1

if rem == 0:
    print(0) # Дробь конечная, периода нет
else:
    print(pos - remainders[rem])
```

### ТИП 6: Системы счисления и маски разрядов

**Задача 6. «Особые переводы»**

Дано натуральное число $N$ в десятичной системе счисления ($1 \le N \le 10^9$). Необходимо перевести его в 9-ричную систему счисления и определить, содержит ли полученная запись подстроку из трех одинаковых цифр подряд. Если содержит, вывести эту цифру, если нет — вывести `NO`. Ограничение по памяти: строку целиком не собирать, анализировать цифры в процессе деления.

- **Ввод:** `242` $\to$ **Вывод:** `NO` ($242_{10} = 268_9$).
    
- **Ввод:** `728` $\to$ **Вывод:** `0` ($728_{10} = 1000_9$, три нуля подряд, выводим 0).
    

**Решение для проверки:**



```Python
n = int(input())

prev_digit = -1
streak = 0
result_digit = -1

while n > 0:
    digit = n % 9
    if digit == prev_digit:
        streak += 1
    else:
        streak = 1
    
    if streak == 3:
        result_digit = digit
        
    prev_digit = digit
    n //= 9

if result_digit != -1:
    print(result_digit)
else:
    print("NO")
```

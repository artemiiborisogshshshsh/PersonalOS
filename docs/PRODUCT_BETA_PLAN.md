# План до закрытой беты

Статус на 09.09.2026: действующий Telegram-прототип для одного разрешённого
чата. Наличие отдельных классов AI и ProposedCommand не означает готовый
голосовой продукт. Голосовые сообщения текущий обработчик пропускает;
IntentInterpreter содержит заглушки. Публичная многопользовательская версия
ещё не готова.

Импорт прошлогодних расписаний отложен по решению пользователя.
Работа идёт последовательно: надёжность → голос/текст → адаптация →
несколько пользователей → закрытая бета.

Проверено 09.09.2026: 313 локальных тестов проходят. Исправлены поиск
субботнего учебного слота с 10:00, запрет рабочей подготовки в паузах до
окончания субботней учебной части, округление по сетке без попадания в
прошлое. Рабочий планировщик ограничивает воскресенье подготовками к
понедельнику после 10:00. Учебный план получает recovery после работы.
Отдельные workflow рассчитывают замену до отката; тесты подтверждают
сохранение старой операции при ошибке чтения занятого времени.

Продолжение: 315 локальных тестов прошли. `/preparations`, кнопка
перепланирования и обновление TPU при подключённом AlfaCRM направлены в
общую очередь. Публикация сохраняет признак незавершённой операции до
записи и Google ID после каждого успешного блока. Проверен сценарий:
первая запись успешна → вторая неуспешна → перезапуск → продолжение той же
операции без повторной вставки первого события. Неподтверждённый update
больше не вызывает автоматический insert; ошибки подтверждения/отката
не маскируются успехом.

Следующее продолжение: 317 тестов прошли. Добавлен журнал
`shared_preparation.json`: освобождение рабочей части → учебная часть →
рабочая часть → завершено. Повторный запуск после ошибки расчёта или
публикации работы продолжает рабочую часть без перестроения уже готовой
учебной. Оба сценария проверены через восстановление workflow с диска.
Журнал переносится вместе с пользовательскими снимками операций.

Следующая проверка: 320 тестов прошли. Воспроизведён сбой после публикации
учебной части, но до записи её этапа в общий журнал; при восстановлении
готовая часть не пересоздаётся. Отдельные study/work replan сохраняют ID
операции и не обращаются к записи Calendar, если рассчитанный план и
названия блоков не изменились. При изменении учебной операции во время перерыва
общий workflow начинает новый расчёт от актуальной версии.

Текущая проверка: 321 тест прошёл. Общая очередь сначала рассчитывает обе
части без записи, исключая собственные старые проекции из занятого времени.
Рабочая часть проверяется с занятостью от нового учебного расчёта. При
совпадении обоих планов сохраняются ID операций и событий; повторный
запуск после восстановления с диска не делает insert/update/delete.
Новая внешняя встреча делает сравнение отрицательным и требует пересчёта.

Первый этап пока не закрыт: требуется сквозная проверка общего пересчёта
через все Telegram-входы и при частичной ошибке записи в Calendar.
Журнал обеспечивает продолжение операции, но не атомарную транзакцию
двух календарей: во время сбоя части плана могут иметь разные версии до
успешного продолжения. Живой Calendar в этой проверке не изменялся.

## 1. Надёжное расписание

- Исправить неделю TPU: 1, 2, 3… по понедельникам; учесть местную дату,
  повторные запуски, переход года и индивидуальную точку отсчёта источника.
- Проверить общий план учебных и рабочих подготовок на реальном наборе данных:
  суббота после 10:00, сначала университет, затем работа; отсутствие
  пересечений, отдельная подготовка к каждой паре, дорога и recovery.
- Проверять порядок также при разрывах между учебными подготовками: рабочие
  блоки не должны заполнять эти разрывы до завершения учебной части.
- Проверить все входы: команды, кнопки, обновления источника, восстановление
  процесса. Локальные тесты не заменяют проверку опубликованного календаря.
- Ошибка источника или Calendar не должна считаться отсутствием занятий.

## 2. Голос и свободный текст в Telegram

- Принимать voice, ограничивать размер/длительность, проверять пользователя.
- Подключить реальное распознавание речи через заменяемый адаптер; выбрать
  провайдера и определить стоимость до включения для пользователей.
- Голос и текст направлять в один обработчик намерений. Поддержать запрос
  плана, создание задачи, перенос подготовки, изменение длительности,
  постоянное отключение подготовки по предмету, feedback.
- Показать «Я понял так…»: объект, дата, время, область действия
  (один раз/всегда), последствия. Кнопки подтвердить, исправить, отменить.
- Неоднозначные названия разрешать выбором конкретного события. Даты
  «завтра» рассчитывать в часовом поясе пользователя.
- Выполнять подтверждённый ProposedCommand через Application Layer;
  сохранить ограничения источников TPU и AlfaCRM и проверку конфликтов.
- Защитить повторные Telegram updates и нажатия от повторного выполнения.
- Удалять временные аудиофайлы после обработки; объяснить передачу аудио
  провайдеру и дать управление хранением истории.
- Приёмка: голос → текст → предложение → подтверждение → один результат
  в Calendar; ошибки распознавания и сети оставляют понятный ответ.

## 3. Адаптация и feedback

- Добавить агента регулярной проверки расписания: искать конфликты,
  нарушения сроков и нагрузки; предлагать переносы подготовок по времени
  и дням, проверять результат детерминированным планировщиком.
- Разрешённые переносы применять автоматически с отчётом «что и почему»;
  неподвижные пары TPU/AlfaCRM сохранять. Повторная проверка без новых
  обстоятельств не должна перетасовывать уже допустимый план.
- Сохранять фактические минуты, выполнение, сложность, комментарии.
- Объяснять каждую предложенную корректировку длительности/расписания.
- Соблюдать согласованный максимум блока 120 минут и права на перемещение.
- Проверить адаптацию на повторных занятиях, а не только отдельный AI-класс.

## 4. Несколько пользователей

- Заменить единственный allowed_chat_id полноценными аккаунтами.
- Разделить источники, OAuth, предпочтения, историю команд и операции
  каждого пользователя; тестировать запрет доступа к чужим данным.
- Onboarding: часовой пояс → Google → расписание → посещаемость → сон →
  первый понятный preview. AlfaCRM подключается при необходимости.
- Фоновый worker и расписание задач по времени пользователя, постоянное
  хранилище, блокировки одновременных пересчётов, восстановление после сбоя.
- Экспорт/удаление аккаунта, отзыв Google-доступа и секреты вне репозитория.

## 5. Закрытая бета и продвижение

- Прогнать полный сценарий нового пользователя без ручного редактирования
  файлов и терминала; отдельно проверить возврат после недельного перерыва.
- Настроить мониторинг неуспешных синхронизаций, резервные копии и поддержку.
- Подготовить описание обработки данных, условия, бюджет AI и лимиты функций.
- Начать с небольшой группы приглашённых пользователей и измерять:
  завершение onboarding, первый план, успешность синхронизации, исправления
  голосового ввода, использование спустя неделю.
- После стабильной беты подготовить демонстрацию, страницу продукта,
  понятные тарифы и публичный запуск. Не обещать возможности, не проверенные
  в полном пользовательском сценарии.

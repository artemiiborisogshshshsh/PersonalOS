# Публичные страницы MyAiCalendar

Существующий HTTP-сервер авторизации Google отдаёт статические страницы без входа:

- `/` — описание бота, доступ в бету и поддержка.
- `/privacy` — политика конфиденциальности.
- `/styles.css` — локальные стили без внешних шрифтов, скриптов и аналитики.
- `/healthz` — прежняя проверка работоспособности.

Исходники находятся в `web/public`. HTTP-маршруты имеют фиксированный список
файлов: пользовательские состояния, секреты и произвольные файлы репозитория
через сервер не доступны. Маршрут `/google/oauth/callback` сохранён.

На существующем сервере Amvera в Google Auth Platform → «Брендинг» укажите:

- Главная страница: `https://personalos-borisov1artemii1.mia0.amvera.tech/`
- Политика: `https://personalos-borisov1artemii1.mia0.amvera.tech/privacy`

Ссылки становятся доступны после успешной выкладки коммита с этими страницами.
Сервер стартует при настроенном Google OAuth. Команда `/privacy` в приглашённом
боте выводит ссылку, используя домен настроенного `GOOGLE_OAUTH_REDIRECT_URI`.

Публичная политика описывает текущую работу сервиса: удаление по запросу в течение
30 дней. Автоматическое удаление после 30 дней неактивности пока не включено;
будущий срок из `PRIVACY_POLICY_DRAFT.md` нельзя объявлять действующим до
реализации и проверки удаления. Копии, создаваемые оператором, должны удаляться
не позднее соответствующих основных данных.

Синтетическая проверка: `python3 -m pytest tests/test_public_pages.py tests/test_invited_beta.py -q`.

# Операторская инструкция: реферальные группы

Этот локальный CLI показывает пожизненные агрегаты по реферальным кодам и
позволяет оператору назначать им рабочие метки лидера и группы. Метки служат
для организации отчётов и сами по себе не меняют пользователя, который
пригласил другого, состояние доступа, скидку или начисление бонуса.

## Безопасность и границы отчёта

- Используй только существующий приватный `access_billing.sqlite3` из
  настроенного state-каталога. Не подставляй путь к production-файлу наугад и
  не запускай команду от пользователя с лишним доступом к state.
- Все команды читают существующий журнал; опечатка в пути не создаёт новый
  журнал или пользователя. Команды меток по умолчанию только показывают
  preview. Для изменения требуется `--apply`.
- Отчёт содержит реферальный код, ручные метки, числа и процент конверсии.
  Он не раскрывает Telegram ID, имена приглашённых, контактные данные или
  список участников. Имя или псевдоним старосты и название группы указывай
  вручную по согласованию со старостой. Не добавляй данные приглашённых,
  контакты, токены и другие секреты.
- Счётчики lifetime: `invited` — количество известных участников,
  привязавших этот код; `published` — привязанные участники, у которых
  отмечена первая публикация плана. Сроковые фильтры и исторические когорты
  не поддерживаются. Для старого пользователя метка первой публикации может
  отражать дату первого наблюдения новой системой, а не фактическое прошлое
  событие. Не интерпретируй эти данные как восстановленную историю.
- Конверсия рассчитывается как `published / invited * 100`; при нулевом
  знаменателе отображается 0%. Групповые итоги складывают все коды с одной
  меткой. Одинаковые названия групп допустимы.
- CSV создаются с UTF-8 BOM для табличных редакторов и режимом доступа только
  владельцу. В ячейках с формульными префиксами добавляется защитный апостроф.
  Пути двух выгрузок должны отличаться и не существовать заранее: команда
  никогда не перезаписывает существующие файлы. При ошибке публикации второго
  файла CLI удаляет уже созданный первый файл, если он всё ещё принадлежит
  этой операции.
- Это не команда Telegram и не платёжная операция. Не отправляй отчёты или
  выгрузки участникам; не публикуй их во внешних сервисах.

## Выбрать журнал

Команда `/referral_stats` в Telegram намеренно не добавлена: текущая проверка
личного чата подтверждает участника, но не назначает ему права администратора.
Для такой команды нужен отдельный список числовых Telegram ID администраторов
из доверенной конфигурации владельца и проверка отправителя до чтения отчёта
или отправки CSV. Имя пользователя, реферальный код и название группы не могут
служить авторизацией. До появления этой проверки отчёты доступны только
локальному оператору с доступом к приватному журналу.

Передавай точный путь существующего приватного общего журнала в `--ledger`.
Не копируй SQLite-файл, пока запущенный процесс может в него писать.

```sh
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 report
```

Команда выводит время создания отчёта, общие итоги, строки по каждому коду и
сводку по меткам групп.

## Искать коды и проверять метки

Поиск без флагов показывает все коды. Поиск по лидеру и группе нечувствителен
к регистру и использует частичное совпадение:

```sh
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 search --leader "Анна"
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 search --group "осень"
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 labels
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 unassigned
```

`unassigned` показывает код, если отсутствует лидер, группа или обе метки.
Пустые значения в обычной команде `search` можно включить флагом
`--unassigned` вместе с другими фильтрами.

## Назначить или очистить метку

Сначала посмотри preview. В `label` нужно указывать обе метки; передай пустую
строку для любого неизвестного значения. Значения ограничены длиной 200
символов и не могут содержать управляющие символы или пробелы по краям.

```sh
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 \
  label КОД --leader "Анна Петрова" --group "Осень 2026"
```

После проверки применяй те же параметры с `--apply`:

```sh
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 \
  label КОД --leader "Анна Петрова" --group "Осень 2026" --apply
```

Очистка тоже сначала показывает preview и пишет только с `--apply`:

```sh
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 clearlabel КОД
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 clearlabel КОД --apply
```

Каждая команда проверяет, что код уже есть в журнале. Она не создаёт аккаунт
или новый реферальный код.

## Выгрузить CSV

Создай новые непересекающиеся пути в каталоге, доступном только оператору.
Укажи точные целевые имена; если хотя бы один файл уже есть, выбери другие
имена, чтобы не перезаписать предыдущую выгрузку.

```sh
python3 scripts/referral_admin.py --ledger /private/state/access_billing.sqlite3 export \
  --codes /private/operator/referral-codes.csv \
  --groups /private/operator/referral-groups.csv
```

Файл кодов содержит код, лидера, группу, агрегаты приглашений/публикаций,
процент и `generated_at`. Файл групп содержит групповые суммы и тот же момент
создания отчёта. Оба файла являются снимками всего доступного журнала, без
фильтра по датам.

## После работы

Проверь preview перед каждой записью метки. Храни CSV только столько, сколько
нужно для операционной сверки, затем удали их безопасным способом. Не меняй
SQLite напрямую: используемый API проверяет существование кода и выполняет
изменение журнала транзакционно. Для резервного копирования и восстановления
смотри [инструкцию по резервным копиям](BETA_STATE_BACKUP.md).

## Закреплённый кандидат и чистый прогон

Кандидат фиксируется локальным коммитом в `codex/update-1`, затем проверяется
в отдельной чистой Git-копии именно этого SHA с закреплёнными зависимостями.
Фактические SHA, fingerprint, exit code полного pytest и чистота до/после
фиксируются в локальном отчёте:
[/private/tmp/myaicalendar-release-rehearsal-20261028/candidate-verification.json](/private/tmp/myaicalendar-release-rehearsal-20261028/candidate-verification.json).
Только отчёт со статусом `verified` закрывает этот пункт; рабочая копия либо
одни целевые тесты сами по себе его не закрывают. Не использовать другой SHA
для выпуска без соответствующей повторной проверки.

## Отложено отдельно, не входит в текущий выпуск

- OCR расписания: следующая обнова; фото конспектов остаются сейчас.
- Реальные платежи: ближайший патч/обновление после выбора провайдера/тарифов.
  До подключения нужны резервирование скидки, подтверждения, поздние события
  и возвраты. Тестовый симулятор их не заменяет.
- У пользователя нет второго Telegram-аккаунта. По согласованному сценарию
  друзья синтетические; изоляция двух реальных транспортных аккаунтов не
  заявляется живой проверкой, программная изоляция покрыта автотестами.

## Единственное разрешение, оставленное на потом

Отдельное решение пользователя о выпуске. До него не деплоить, не менять
manifest на опубликованный и не отправлять анонс.
